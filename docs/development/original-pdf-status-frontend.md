# Original PDF status (frontend only)

The CV library, library review, simulation progress and simulation results use the same `OriginalPdfStatus` component and state mapper. Status is independent of confirmation, publication, prediction completion and the retention of structured facts or approved model inputs.

Library records confirm absence only when `originalAvailable === false`. This wording also supports revised copies which never had a PDF. An explicitly present temporary original (`temporary_original` 1/true) is pending cleanup only after confirmation; a legacy record or one with missing temporary-file metadata is shown as still stored, without promising automatic deletion. Missing or malformed availability flags show unknown. The existing manual cleanup endpoint is offered only for confirmed temporary records whose current revision was published, as required by `ResumeService.cleanupOriginal`.

Case status maps explicit `cleanupStatus` COMPLETE to no original stored, PENDING to pending and FAILED to failed. Missing/unrecognized values and NONE after confirmation remain unknown. NONE before confirmation describes planned cleanup without claiming a PDF was uploaded (library reuse may create a case without one). The cases store clears cached cleanup proof when a new status response omits the field. Demo pages explicitly describe a simulation and do not claim server deletion.

Pending cleanup refreshes every 10 seconds while its page is open. Refresh stops after a terminal/unknown status, a failed status read, disabled operations or unmounting. Users can refresh manually; the existing simulation progress polling continues independently while assessments run. A network error preserves the last reported state and labels it as such. Authorization/not-found responses clear the case rather than retaining inaccessible content. Library metadata refresh updates only original-file fields, preserving unsaved edits and the review acknowledgement.

No backend cleanup, DeepSeek, retention, database, publication or scoring behavior changed. In particular, historical originals excluded from temporary cleanup cannot be deleted by this frontend change; the teacher's deletion promise needs a backend decision for those records. The frontend does not infer PDF deletion from removal of model inputs or guarantee immediate physical deletion at confirmation.

Validation: `frontend/tests/original-pdf-status.test.js` covers absent/missing flags, pending and legacy originals, revision-gated retry, independent case states, metadata-only refresh, cached status invalidation and rendering in all three languages. Local browser fixtures verify pending-to-complete updates, unknown and network-error messages, cleanup retries and preservation of unsaved edits. Real storage deletion requires backend integration verification.

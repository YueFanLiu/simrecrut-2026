# Simplified case review (frontend only)

The connected and demo review pages now offer **Save All Changes** and **Confirm and Continue**. Optional research/model settings start collapsed. Confirmation still requires an explicit review acknowledgement; editing facts, empty-section acknowledgements or optional inputs resets it. Confirmation navigates to simulation progress; running predictions remains a separate action.

Connected mode uses existing endpoints in sequence: save changed facts, reload canonical facts, save changed research attributes, save model inputs when the protocol supports them, then confirm. Every write uses the latest returned revision and its own idempotency key. This is a sequence of existing operations, not an atomic backend transaction: a failure can leave earlier sections saved. Validation errors keep the page editable; a lost response freezes edits and offers **Retry Previous Save**, preserving the original payload/key and completed stages. Confirmation retries reuse the receipt even when the case is already locked. Revision conflicts require reloading the saved draft; unsaved edits are protected by a discard prompt.

Saving facts regenerates model text on the backend. Text manually edited during the current page session and portrait choices are preserved. Otherwise the frontend reloads automatic text against the new revision. If enabled text changes, the save flow pauses before model approval or confirmation, opens optional settings and requires a new review acknowledgement. The previous text remains recoverable through an explicit restore button, including custom text saved in a previous session whose provenance the backend does not expose. Untouched automatic text is never silently written back over the regenerated version. Text and portrait use are never enabled implicitly. When text is omitted, blank name/biography are sent so hidden extracted contact details cannot prevent omission. Research values remain UNKNOWN unless the user changes them. Demo optional research retains its separate explicit acknowledgement when supplying non-UNKNOWN values.

Unsubmitted skill edits/additions and section-creation forms report pending state to every shared-editor page. Whole-CV save, confirmation and revision export wait until these local forms are submitted or cancelled. Starting an edit resets the review acknowledgement and prevents switching away from the active editor tab. Temporary operation locks retain local input instead of clearing it.

No backend API, DeepSeek prompt, extraction or scoring logic was changed. The PDF notice now describes deletion being queued after confirmation; this frontend change does not verify physical deletion or alter cleanup timing.

`frontend/tests/case-review-flow.test.js` covers save ordering, revisions, omission, manual input preservation, regenerated-text review, partial-success recovery, read retries, lost confirmation receipts and conflicts. `cv-review-regressions.test.js` runs actual SFC setup/actions to cover unfinished-editor guards and delayed restore races. Browser checks use synthetic data and a disposable local API fixture; real-service integration still depends on the existing backend.
